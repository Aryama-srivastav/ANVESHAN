# Security Policy

## Scope and data safety notice

ANVESHAN is currently intended for development, research, and prototype use.

Do **not** submit or commit real investigation records, personally identifiable information (PII), victim or witness data, confidential government information, credentials, private keys, or production data to this public repository.

Use only synthetic or fully anonymized test data.

## Reporting a vulnerability

Please report suspected vulnerabilities privately to **[SECURITY CONTACT]**.

Do not open a public issue for exploitable vulnerabilities.

## What to include in a report

Provide enough detail for maintainers to reproduce and assess the issue:

- A clear summary and affected component(s)
- Impact assessment (confidentiality, integrity, availability)
- Reproduction steps or proof of concept
- Affected versions/branches and environment details
- Suggested remediation (if known)

## Responsible disclosure expectations

- Give maintainers a reasonable remediation window before public disclosure.
- Coordinate disclosure timing after a fix or mitigation is available.
- Do not publicly disclose exploit details before remediation is released.

## Sensitive-data handling

- Never include real evidence, case files, personal records, or secrets in reports.
- Redact all sensitive fields from logs, screenshots, and payload samples.
- If sample data is needed, provide synthetic/anonymized data only.
